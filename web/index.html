PeekMicrobiome upload-free, installation-free metagenomic profiling across biomes

Easy in-browser multi-sample metagenomic profiler

Drop FASTQs, or paste an ENA accession — each sample is profiled against one MGnify biome catalogue, locally in your browser, and the results are assembled into a relative-abundance matrix. If you do not know the biome, the page can work it out from one sample.

Your own files never leave your computer. FASTQs you drop here are read, decompressed and profiled entirely inside this browser tab. Nothing about them — not the reads, not the file names, not the results — is uploaded anywhere. That is true in every mode, whatever else this page does, and it is the reason the tool exists.
This page does make two kinds of request of its own — downloading a reference database, and downloading public ENA reads if you ask for them. Both are downloads towards you, and each is explained at the control that makes it. Nothing of yours is ever sent anywhere.
Quick-and-dirty preview. This tool is meant for fast in-browser checks of metagenomic composition, against one MGnify catalogue at a time. It does not achieve the reliability of sylph, MetaPhlAn4, or Meteor2 run natively — use those for real analyses. This is an unofficial adapted WebAssembly port of sylph — not supported or endorsed by the sylph authors. If you use the results, please cite the sylph paper (Shaw & Yu, Nat. Biotechnol. 2024) and the MGnify genome catalogue you actually loaded — for the human gut that is the UHGG catalog (Almeida et al., Nat. Biotechnol. 2021), and each of the other eighteen has its own paper.

1Reference database

Choose the catalogue:
Screens the first sample against a 13 MB marker set, then loads the catalogue it points to.
Loading a reference database downloads it from zenodo.org. The human-gut (UHGG) database is 433 MB; the others run from 12 MB (zebrafish-fecal) to 2.8 GB (soil). It is fetched the first time you click Load database, then kept on this computer for later visits. Zenodo sees your IP address and which of these files you asked for. The bundled 6 MB smoke-test database, or a .syldb from your own disk, downloads nothing at all.
The catalogues cannot be combined: MGnify dereplicates each one separately and they overlap, so loading two would count the same species twice. The loaded biome is named on the database line, above the matrix, and inside every TSV and CSV you download; that is where a mistake is caught.

2Samples

or
…or profile public data from the ENA run, sample, experiment or project accession
Paste a run, sample, experiment or project accession — nothing is permanently saved to your disk, the reads are streamed straight into the profiler. This mode downloads public FASTQs from the EBI. This page asks the EBI's public ENA API which files an accession covers, then streams those public FASTQs from the EBI's servers (any host under ebi.ac.uk — usually ftp.sra.ebi.ac.uk) straight into the profiler, without ever writing them to your disk. The EBI therefore sees your IP address and which accessions you looked up, exactly as it would if you downloaded them yourself.
      Fewer reads finish sooner; more reads detect species at lower abundance.
      Very high read counts can exhaust this browser's memory and abort the run. The exact limit depends on your browser and is worked out for you here.

      What this page is allowed to use

      There is no separate network control, because there is nothing separate to control: each worker downloads the sample it is profiling, so workers is also the number of simultaneous streams. A page cannot cap a transfer rate, and a dial that pretended to would be worse than none.
