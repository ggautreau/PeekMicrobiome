PeekMicrobiome upload-free, installation-free metagenomic profiling across biomes

Quick multi-sample metagenomic profiler

Drop several FASTQs — each is profiled against the reference catalogue you choose (one MGnify biome at a time), locally in your browser, and the results are assembled into a relative-abundance matrix.

Your own files never leave your computer. FASTQs you drop here are read, decompressed and profiled entirely inside this browser tab. Nothing about them — not the reads, not the file names, not the results — is uploaded anywhere. That is true in every mode, whatever else this page does, and it is the reason the tool exists.
This page does make two kinds of request of its own, and both are downloads towards you. Nothing of yours is ever sent anywhere.
Loading the reference database downloads it from zenodo.org. You choose which biome's catalogue to load: the human-gut (UHGG) database is 433 MB, the others run from 12 MB (zebrafish-fecal) to 2.8 GB (soil). It is fetched the first time you click Load database, then kept on this computer for later visits. Zenodo sees your IP address and which of these files you asked for. Choosing the bundled 6 MB smoke-test database, or a .syldb from your own disk, downloads nothing at all.
The ENA mode below downloads public FASTQs from the EBI. If you paste an accession, this page asks the EBI's public ENA API which files it covers and then streams those public FASTQs from the EBI's servers (any host under ebi.ac.uk — usually ftp.sra.ebi.ac.uk) straight into the profiler, without ever writing them to your disk. The EBI therefore sees your IP address and which accessions you looked up, exactly as it would if you downloaded them yourself.
Quick-and-dirty preview. This tool is meant for fast in-browser checks of gut metagenomic composition. It does not achieve the reliability of sylph, MetaPhlAn4, or Meteor2 run natively — use those for real analyses. This is an unofficial adapted WebAssembly port of sylph — not supported or endorsed by the sylph authors. If you use the results, please cite the sylph paper (Shaw & Yu, Nat. Biotechnol. 2024) and the UHGG catalog (Almeida et al., Nat. Biotechnol. 2021) — or, for any other biome, the MGnify genome catalogue you loaded.
Pick the biome your samples came from. Every result is relative to the one catalogue you loaded and to nothing else: sylph names the closest genomes that catalogue contains and says nothing at all about species it does not contain. Profiling a saliva sample against the soil catalogue therefore returns a full, plausible, wrong table — with no error and no empty result. The loaded biome is named on the database line, above the matrix, and inside every TSV and CSV you download; that is where a mistake is caught. The catalogues cannot be combined: MGnify dereplicates each one separately and they overlap, so loading two would count the same species twice.
