Drop one FASTQ — it is sketched and profiled against the MGnify catalogue you choose (one biome at a time), locally in your browser. Nothing is uploaded.

100% browser-based — your files never leave your computer. The FASTQ you drop here is read, decompressed and profiled entirely inside this browser tab. Nothing about it — not the reads, not the file name, not the results — is uploaded anywhere.
Loading the reference database downloads it from zenodo.org. You choose which biome's catalogue to load: the human-gut (UHGG) database is 454 MB, the others run from 13 MB (zebrafish-fecal) to 3.0 GB (soil). It is fetched the first time you click Load database, then kept on this computer for later visits. Zenodo sees your IP address and which of these files you asked for. Choosing the bundled 6.5 MB smoke-test database, or a .syldb from your own disk, downloads nothing at all. That download is the only request this page makes, and it only travels towards you.
A peek, not a definitive answer. This tool gives you a fast look at gut metagenomic composition in the browser. It does not achieve the reliability of sylph, MetaPhlAn4, or Meteor2 run natively — use those for real analyses. This is an unofficial adapted WebAssembly port of sylph — not supported or endorsed by the sylph authors. If you use the results, please cite the sylph paper (Shaw & Yu, Nat. Biotechnol. 2024) and the UHGG catalog (Almeida et al., Nat. Biotechnol. 2021) — or, for any other biome, the MGnify genome catalogue you loaded.
Pick the biome your sample came from. Every result is relative to the one catalogue you loaded and to nothing else: sylph names the closest genomes that catalogue contains and says nothing at all about species it does not contain. Profiling a saliva sample against the soil catalogue therefore returns a full, plausible, wrong table — with no error and no empty result. The loaded biome is named on the database line and above the results table; that is where a mistake is caught. The catalogues cannot be combined: MGnify dereplicates each one separately and they overlap, so loading two would count the same species twice.

Pick the biome your sample comes from and click Load database. The first load downloads that database once; it is then kept on this computer — unless the browser evicts it to reclaim disk space — so later visits start instantly.

Fewer reads finish sooner; more reads detect species at lower abundance.
Very high read counts can exhaust this browser's memory and abort the run. The exact limit depends on your browser and is worked out for you here.
